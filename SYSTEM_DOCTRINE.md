# ⚛︎ System Doctrine: DrMarchand’s OS™

## 🗺️ Map → 🧠 Remember → 🔍 Compare → 🛠️ Create → 🧪 Prove → 🗄️ Preserve

Owning business context: Design Orchard LLC d/b/a DrMarchand’s Laboratory  
Doctrine type: System Operating Doctrine  
Purpose: Preserve continuity, provenance, lineage, evidence, identity, and human authority across an evolving creative/computational system.

> Historical lineage note: this doctrine is a descendant, not a replacement. MAP discovery recovered a Design Orchard OS Starter artifact dated 2026-06-11. Its preserved state and lineage record live under `registry/lineage/`.

## I. Purpose and Core Invariants

Map before create. Search durable evidence before treating a new name as a new thing. Preserve identity, provenance, genesis, and lineage. Evidence does not create authority. Registration does not imply execution. Ownership must be explicit. When evidence cannot resolve identity or lineage, preserve uncertainty and return the decision to the authorized human.

## II. Discovery and Memory

Before constructing architecture, ask what already exists and what is related. Search Library and Bookshelf records, databases, files, repositories, infrastructure, scripts, APIs, timestamps, registries, lineage records, checksums, execution receipts, and Atlas/MAP evidence. System memory recovers, presents, and preserves evidence; it does not rewrite history.

## III. Genesis and Lineage

Preserve the first genuinely working state. Evolution proceeds through version, descendant, branch, clone, composition, or merge. A merge may have multiple parents. MERGE ≠ DELETE. DESCENDANT ≠ REPLACEMENT. LEGACY ≠ IRRELEVANT. Connection does not require collapse.

## IV. Identity, Ownership, and Authority

Keep idea, method, name, expression, artifact, author, contributor, copyright owner, business entity, DBA, entity owner, publisher, custodian, runtime authority, and publication authority as distinct attributes. Resolve ownership from provenance and evidence rather than filesystem location, database placement, branch membership, or custody.

## V. Lifecycle and Proof

A useful lifecycle is `⚛︎ Template → 📝 Draft → 🔬 Proof → 🌳 Publication`, while recognizing that copyrightable expression need not originate from Template or traverse every stage. Proof is evidence, not authorization. Successful execution, similarity, connectivity, registration, or API availability does not silently create ownership or authority.

## VI. Custody, Registry, Permission, and Exposure

The Library provides custody and discovery; presence does not authorize execution or publication. Registry records identity, lineage, evidence, eligibility, and scoped permissions. Exposure through an API or runtime must pass identity, integrity, proof, eligibility, permission, safety, policy, and publication gates appropriate to the artifact.

## VII. Language, MAP, and Branches

Alphabet and language provide indexing and resolution; they do not determine meaning or authority. MAP is both operation and resolvable word-object. Business and creative branches remain distinct. Design Orchard LLC may provide legal/business context while DrMarchand’s Laboratory and KEJ Studio lanes preserve their own operational responsibilities and artifact provenance.

## VIII. Operating Rules

Begin with the smallest useful read-only discovery pass. Two nodes are sufficient when they can establish identity, location, objects, relationships, provenance, evidence, differences, and uncertainties. Keep doctrine, runtime record, and evidence separate:

```text
SEED       = how the system reasons
RECORD     = what is asserted about this work
EVIDENCE   = why the record may be trusted
```

## IX. Operating Loop

`REMEMBER → DISCOVER → MAP → COMPARE → DISTINGUISH → CREATE → TEST → PROVE → REGISTER → PRESERVE → PUBLISH → MAP AGAIN`

## X. Human Authority

The system carries continuity and presents evidence. The authorized human retains judgment and authority. Where evidence cannot establish whether artifacts are duplicates, descendants, aliases, independent expressions, or different concepts, preserve both and record the uncertainty.

## XI. Doctrinal Core

Connection does not require collapse. Evolution does not require erasure. Memory does not require human recollection. Evidence does not create authority. The map remembers; the human decides.

## XII. Runtime Binding

Runtime values are evidence-backed assertions rather than inherited defaults.
